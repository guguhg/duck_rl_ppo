**一句话概括**：能走了 → 会歪 → 修好歪 → 侧移学不会 → 补采样 → 歪回来 → 加航向奖励治好歪但压死转向 → 门控分开处理 → 收紧直行 → 加域随机化。

**九轮里真正的突破只有五次**：修归一化（第 2 轮）、加 yaw 观测（第 3 轮）、改指令采样（第 4 轮）、
heading 门控（第 7 轮）、域随机化（第 9 轮）。其余四轮（含失败的 exp1、exp5）产出的是**排除法**——
排掉一条错路，本身也是进展。

## 二、逐轮详解

### 第 1 轮：18M 步，完全失败

**假设**：写完 env 就能训出来。

**结果**：`eval_reward` 从 121 涨到 2029.9（看起来很好），但实测只会站——指令 0.1 时 5 秒只挪 1.6 cm。

**根因（第 2 轮才发现）**：`export_onnx.py` 默认 `normalize=False`，而训练用的 BerkeleyHumanoid 配置里 `normalize_observations=True`。  
更糟的是 `verify_onnx` 重建 JAX 参考网络时**也没传 `preprocess_observations_fn`**——两边都少同一步，误差 4.9e-07 通过，是**假阳性**。

**教训**：`eval_reward` 涨不代表行为对。验证"导出是否等价"时，参考实现必须和训练路径用同一套预处理，否则等于自己跟自己比。

---

### 第 2 轮：32.7M 步，第一次真正走起来

**改了什么**（修完归一化之后，同时改了 4 个超参）：

| 参数               | 旧 → 新           | 理由                      |
| ---------------- | --------------- | ----------------------- |
| `action_scale`   | 0.3 → **0.45**  | 0.3 时关节只能摆 ±17°，物理上迈不开腿 |
| `w_tracking_lin` | 1.5 → **2.5**   | 抬高"走起来"的分               |
| `w_alive`        | 1.0 → **0.3**   | 白给分从占 23% 压到 7%         |
| `sigma_lin`      | 0.25 → **0.08** | 原来误差 0.4 m/s 只扣一半分，太宽容  |

**结果**：0.38 m/s（指令 0.4），达成率 95%。

**为什么改这 4 个**：第 1 轮的失败除了归一化，还有"站着能拿 84% 的分"这个结构问题。  
量化过——指令 0.4 时站着拿 3.6 分、完美跟踪 4.3 分，只差 16%，策略没动力冒险。  
改完差距拉到 88%。

**新问题**：30 秒后掉头，`x` 从 +4.2 退回 +1.3。

### 第 3 轮：40.96M 步，加 yaw 观测

**诊断**：观测里**根本没有朝向信息**。

| 观测分量           | 绕 z 轴转 180° 时的反应         |
| -------------- | ------------------------ |
| `gravity`（3 维） | **完全不变**——重力在体系里的投影与偏航无关 |
| `gyro`（3 维）    | 只给瞬时角速度，不知道"已经转了多少"      |
| `q` / `qd`     | 关节量，不含躯干朝向               |

所以微小偏航偏差没有任何信息能纠正，走十几秒就累积成掉头。

**改动**：`OBS_LAYOUT` 末尾加 `("yaw", 2)`，值取 `[sin(Δyaw), cos(Δyaw)]`，Δyaw = 当前航向 − 回合起点航向。51 → 53 维。

用 sin/cos 而不是角度值：角度在 ±180° 会跳变（179 → −179），正弦余弦连续。

**三处必须同步改**（漏一处就静默错位）：  
`constants.py`（契约）、`env.py::_get_obs`（拼接）、`watch_policy.py`（回放手写拼接）。

**结果**：

| 指令            | 实测             | 理论     | 达成     |
| ------------- | -------------- | ------ | ------ |
| 前进 0.4 × 30 s | 11.74 m        | 12.0 m | 97.5%  |
| 转 0.3 × 5 s   | +94.6°         | +86°   | 偏快 10% |
| 转 0.6 × 15 s  | +547.5°（1.5 圈） | +516°  | 偏快 6%  |

原地转 15 秒，前进位移仅 1.4 cm——它学会了把"转"和"走"分开。

### 第 4 轮：40.96M 步，修侧移，结果弄坏直线

**诊断**：`[0, 0.3, 0]`（纯左移）时它往**后退**。

**根因是采样概率**。三维独立均匀采样下，`[0, 0.3, 0]` 这个组合的概率：

| 维度                   | 容差       | 概率    |
| -------------------- | -------- | ----- |
| `vx ∈ [-0.05, 0.05]` | 0.1/1.2  | 8.3%  |
| `vy ∈ [0.25, 0.30]`  | 0.05/0.6 | 8.3%  |
| `wz ∈ [-0.1, 0.1]`   | 0.2/1.6  | 12.5% |

联合概率 **0.087%** → 4 万个回合里只有 **约 35 个样本**。学不会是数学必然。

**改动**（两条）：

```python
# ① 30% 的回合只动一个轴，另两个强制为 0（手柄的实际用法）
axis = randint(3); mask = (arange(3) == axis)
cmd = where(prob < 0.3, cmd * mask, cmd)

# ② vy 有一半概率落在两侧边界 [±0.2, ±0.3]
vy = where(prob < 0.5, edge_mag * sign, vy)
```

**结果**：侧移从"往后退"变成 99.6%，六方向全过。

| 方向      | 达成率            |
| ------- | -------------- |
| 前进 / 后退 | 99.0% / 97.6%  |
| 左移 / 右移 | 99.6% / 98.3%  |
| 左转 / 右转 | 95.3% / 103.3% |

**但 30 秒直线测试暴露新问题**：9.58 m、侧漂 −6.50 m、**偏航 −61.9°**。

5 秒测试（99.0%）完全看不出来，30 秒才露。**这就是为什么不能用 5 秒测试验收直线性。**

---

### 第 5 轮：中途停止，验证一个假设

**假设**：`vy` 边界加权 50% 给了太多"斜着走"的暴露量，泛化到了纯前进。

**改动**：`cmd_vy_edge_prob` 0.5 → **0.25**，其余不动。

**结果**（15M 步中断检查）：15 秒偏航 −30.2°，对照第 4 轮同期约 −35.7°，**只改善 15%**。

**结论**：调采样治不了漂移。这条路堵死，必须直接约束累积航向。

（这一轮训练没跑完，但它的价值是**排除法**——省下了后面继续瞎调采样的时间。）

### 第 6 轮：44.24M 步，加航向奖励，直线完美但转向死了

**诊断**：`tracking_ang` 治不了漂移的本质

```python
tracking_ang = exp(-(gyro_z - cmd_z)² / 0.25)   # 只约束「此刻转多快」
```

策略可以做到"每一步都几乎不转，这一项拿满分"，但误差逐步累积。  
**类比：只看方向盘是否回正，不看车头朝哪。**

**改动**：加第八项奖励，直接比"车头朝哪"

```python
yaw_cmd = ∫ wz dt                      # 指令积分出的期望航向
heading = exp(-(当前yaw − yaw_cmd)² / 0.1)
```

配套：`w_heading=0.8`、`w_tracking_ang` 0.8→**0.4**（让位）、`cmd_vy_edge_prob` 0.5→0.25。

**角度环绕坑已处理**：偏航在 ±180° 跳变，误差先 `arctan2(sin(e), cos(e))` 归一到 [−π, π]。

**结果**：

| 指标     | 值                                                                        |
| ------ | ------------------------------------------------------------------------ |
| 30 秒前进 | **12.324 m**（102.7%）                                                     |
| 30 秒侧漂 | **−0.019 m**                                                             |
| 30 秒偏航 | **+1.6°**                                                                |
| 六方向    | 前进 100.8% ✅ / 后退 99.9% ✅ / 左右移 93.6% 与 103.0% ✅ / **左右转 −0.0% 与 2.4%** ❌ |

**转向彻底失效**。进一步用 `wz=0.15`（该转 43°）验证，只转 **0.5°**。  
旁证：高度从平时 0.155 抬到 **0.163**，它绷紧身体站住不动。

**根因分析（这一节最重要）**：

纯转向 `wz=0.6` 时，两种行为的理论收益：

| 行为 | `tracking_ang`    | `heading`            | 合计   |
| -- | ----------------- | -------------------- | ---- |
| 转准 | 1.0 × 0.4 = 0.40  | 1.0 × 0.8 = 0.80     | 1.20 |
| 不转 | 0.24 × 0.4 = 0.10 | 平均 0.02 × 0.8 = 0.02 | 0.12 |

理论差 10 倍，本该会转。但 PPO 学不到，因为**梯度断了**：

1. 训练早期策略乱动，转向必然不准 → 误差超 0.6 rad → `exp(-e²/0.1)` 塌到 0.03
2. **梯度也是 0** → "转向"这条路没有任何学习信号，优势估计分不出好坏
3. 同时"不转"能保住 `upright`/`height`/`alive` 满分（1.3 分），姿势最稳
4. PPO 于是选保守：稳拿 1.3，不去赌那个没信号的 1.2

**核心教训**：

> 用 `exp(-e²/σ)` 惩罚累积误差时，σ 太小会让**学习信号在训练早期就消失**。  
> 策略退化成"什么都不做"，因为它至少能保住那些不会饱和的奖励。

### 第 7 轮：36.0M 步，按指令分流，两个都要

**思路**：两个奖励各管一段，不要打架。

- **直行**（`wz≈0`）→ `heading` 全力纠偏（exp6 证明它治得住）  
  |  |  |  |  
  | --- | --- | --- |
- **转向**（`|wz|` 大）→ `heading` 让位，交回 `tracking_ang`（exp4 证明它学得会 95%）

**改动**：

```python
gate = exp(-(wz / 0.25)²)                      # 高斯门控，光滑无跳变
w_eff = w_heading × (0.15 + 0.85 × gate)
```

| 指令 `wz`  | gate  | `heading` 有效权重 | 谁在管             |
| -------- | ----- | -------------- | --------------- |
| 0（直行）    | 1.000 | **0.800**      | heading 全力纠偏    |
| 0.15     | 0.698 | 0.594          | 过渡              |
| 0.25     | 0.368 | 0.370          | 过渡              |
| 0.60（急转） | 0.003 | **0.122**      | tracking_ang 主导 |

配套：`w_tracking_ang` 0.4 → **0.8**（还回去）、`sigma_heading` 0.1 → **0.2**（原值太尖）。

**结果**：

| 方向          | exp6           | **exp7**           |
| ----------- | -------------- | ------------------ |
| 前进          | 100.8%         | **100.4%**         |
| 后退          | 99.9%          | **95.2%**          |
| 左移 / 右移     | 93.6% / 103.0% | **96.1% / 100.3%** |
| **左转 / 右转** | **0% / 2.4%**  | **83.9% / 104.1%** |

**转向从 0% 恢复到 84%**。

**代价**：直线从 1.6° 退到 **21.6°**、侧漂从 1.9 cm 涨到 2.9 m。  
根因是 `sigma_heading` 为了给转向留梯度放到了 0.2，直行纠偏变松。

**为什么不回头调采样**：exp5 已经证明那条路无效。

### 第 8 轮：40.96M 步，sigma 回 0.1 —— **并集拿到了**

**假设**：exp7 的门控已经把两个场景隔离了，所以现在可以把 `sigma_heading` 调回 exp6 的 0.1：

- **直行**（门控=1）：权重 0.8 + σ 0.1 = **与 exp6 完全相同** → 直线应回到 1.6°
- **转向**（门控≈0）：权重只有 0.12 + σ 0.1 → σ 再尖也影响不到转向

**改动**：只有一行

```python
c.sigma_heading = 0.2  →  0.1
```

**这是整个项目里最"干净"的一次实验**：单变量、有对照（exp6 直行参数完全一致）、有理论依据。

**结果：六方向全部通过，且最均衡**

| 方向 | exp7 | **exp8** | 变化 |
|---|---|---|---|
| 前进 | 100.4% | **101.7%** | +1.3 |
| 后退 | 95.2% | **97.1%** | +1.9 |
| 左移 | 96.1% | **93.3%** | −2.8 |
| 右移 | 100.3% | **99.8%** | −0.5 |
| **左转** | 83.9% | **93.7%** | **+9.8** |
| **右转** | 104.1% | **91.3%** | −12.8（过转修正） |

两侧转向变得**对称**了（93.7% / 91.3%），exp7 是 83.9% / 104.1%。这是控制更精确的表现——
之前一快一慢，现在两个方向都接近目标值。而且**没有一项低于 91%**，是当时最均衡的一次（第 9 轮的 96.5% 更好）。

**30 秒直线**：

```
前 +12.310 m / 侧 +0.775 m / 直线距离 12.334 m（0.41 m/s）
累计偏航 +3.0°
高度 0.148~0.157，全程稳
```

**三代对比（核心成就）**：

| 指标 | exp6（直线好） | exp7（转向好） | **exp8（都要）** |
|---|---|---|---|
| 30 秒偏航 | 1.6° | 21.6° | **3.0°** |
| 30 秒侧漂 | 0.019 m | 2.906 m | **0.775 m** |
| 30 秒前进 | 12.324 m | 11.646 m | **12.310 m** |
| 前进 5 秒偏航 | +2.1° | +8.7° | **+0.8°** |
| 左转 / 右转 | 0% / 2.4% | 83.9% / 104.1% | **93.7% / 91.3%** |

偏航 3.0° 略逊 exp6 的 1.6°、侧漂 0.78 m 略逊 0.02 m，但转向从 0% 提到 93.7%——**这是净赢，且幅度极大**。

**关键洞察**：

> 门控的价值不只是"修好了转向"，更是**把两个场景解耦，让参数可以独立优化**。
> 没有门控时，σ 是个「直行 vs 转向」的跷跷板——收紧它转向死，放松它直线漂。
> 有了门控，σ 只影响直行，转向由 `tracking_ang` 与 `heading_gate_floor` 管，两者互不干扰。

这是工程上常见的模式：**当两个需求冲突时，先想办法把它们分到不同作用域，而不是找一个折中的参数值。**

**这一版定为最终主策略：`checkpoints/policy_exp8.onnx`**

### 第 9 轮：域随机化，以及一个比参数更重要的发现

**做法**：不复制整个 model，只把 7 个小数组做成 per-env（照抄 mujoco_playground 的 `locomotion/g1` 模式）：

```
地面摩擦 / 关节库仑摩擦 / 转子惯量 / 各 body 质量 / 舵机 kp / 力矩上限
```

显存代价 ≈ 180 KB（7 个小数组 × 512 环境），实测训练峰值 2.5 GB（exp8 是 2.1 GB）。

接入方式：`ppo.train(randomization_fn=...)` 是 brax 原生支持的，它自己会
`jax.random.split(key, num_envs)` 再 `functools.partial`，不需要改包装层。

**两个必须踩对的坑**：

1. **字段操作要写在 `jax.vmap` 内部**。写在外部对 `(ngeom,3)` 的数组 set 一个 `(N,)`，
   JAX 不会自动加前导维，形状直接错。
2. **`kp` 与 `biasprm[1]` 必须同步**。position 执行器的力 = `gainprm[0]·ctrl + biasprm[1]·q + ...`，
   MuJoCo 自动设为 `gainprm[0]=kp, biasprm[1]=-kp`。只改一个会变成"只有前馈没有反馈"，
   力随 ctrl 线性增长，鸭子会飞出去。验收脚本里专门检查了这一项（`max|biasprm[1]+kp| = 0`）。

**训练结果**（65.5M 步，比设的 40M 多 64%，`num_evals` 量化所致）：

| 指标 | exp8 | dr1 |
|---|---|---|
| eval 奖励 | 2370.5 | 2385.7 |
| `heading` | 366.1 | **426.3**（+16%） |
| `action_rate` | 896.1 | **764.0** |
| `torque` | 24805.8 | **21043.5** |
| 六方向最低 | 91.3% | **96.5%** |

**动作更平滑、更省力**——这是 DR 的典型正向副作用：策略被逼着学会更柔和、更通用的发力方式。

---

#### 核心发现：域随机化只对「既敏感、又训过」的维度有效

用 `scripts/check_robust.py` 在同一引擎下做四维度对照，比较 exp8（无 DR）和 dr1（有 DR）：

| 维度 | 练过？ | exp8 极差 | dr1 极差 | 结论 |
|---|---|---|---|---|
| 地面摩擦 0.30~0.95 | ✓ (0.3,1.0) | 2.7% | 2.0% | 两者都稳——**摩擦本身不敏感** |
| **质量 0.85~1.15** | ✓ (0.9,1.1) | **3.5%** | **1.0%** | ✅ **dr1 稳 3.5 倍** |
| 舵机 kp 0.7~1.3 | ✓ (0.8,1.2) | 19.7% | 17.3% | dr1 略好 |
| **舵机回差 0.5°** | ✗ | 18.2° | 25.2° | ❌ **无优势，甚至略差** |

**为什么摩擦训过却没优势**：因为摩擦对鸭子根本不敏感（足底平面接触、速度只有 0.4 m/s、
不靠蹬地产生推力），基线策略本来就能扛，DR 没有提升空间。

**为什么回差训过就能好**：没训过。回差是齿轮间隙（±0.5° 死区），
我们的 DR 里**完全没有这一项**，所以两个策略都没见过它，好坏纯属随机漂移
（exp8 偏 −18.2°、dr1 偏 +25.2°，方向相反）。

**所以更准确的表述是**：

> DR 的价值在「**既敏感、又训过**」的维度上体现。
> 敏感但没训过（回差）→ 无优势；训过但不敏感（摩擦）→ 无差异。

**工程含义**：做 DR 之前先测敏感度，别盲目随机化一堆参数。测一个维度只要 5 秒
（`check_robust.py` 用 CPU MuJoCo，无编译开销），比训 2 小时便宜得多。

#### 顺带的重要认知：位置伺服天生对 kp 不敏感

kp 从 9.4 到 17.4（±30%）时：

| 策略 | kp0.70 | kp1.00 | kp1.30 |
|---|---|---|---|
| exp8 | 87.3% | 101.0% | 107.0% |
| dr1 | 90.6% | 100.4% | 107.9% |

**只是速度变 20%，两者都没摔。** 原因是位置伺服是**闭环**的：
kp 只决定"多快到达目标"，不决定"到哪里"。只要 kp 大到能克服重力和摩擦，最终位置都会到。

对比力矩控制（直接输出扭矩）：kp 一变输出立刻变，行为完全不同，那种架构下 DR 是生死攸关的。

**BAM 论文选 position actuator 而不是 torque，本身就是一种鲁棒性设计。**

**买硬件的含义**：舵机个体差异不是最大风险，不用纠结挑最一致的舵机。

#### 回差模型的建模技巧（值得记住）

回差不是"参数"，是**额外的自由度**。官方在 `open_duck_mini_v2_backlash.xml` 里，
给每个腿关节后面串了一个只能转 ±0.5° 的限位关节：

```xml
<joint name="left_hip_yaw" .../>           <!-- 伺服驱动这个 -->
<joint name="left_hip_yaw_backlash" class="backlash"/>  <!-- 夹在中间，range=±0.0087 -->
```

物理效果：正转时小关节转到 +0.5° 卡住，力才往下传；反转要先转回 −0.5°。
**1° 的死区**就是这么出来的。

代价：`nq 21→31`、`nv 20→30`（腿 10 个关节 × 2，头颈 4 个没加）。

**由此带来一个代码陷阱**：`qpos[7:7+14]` 这种固定切片在回差模型上会**静默取错**
（取到交错排列的回差关节上）。必须改成按 actuator 顺序索引：

```python
act_jnt_ids = m.actuator_trnid[:, 0]        # (14,) 每个执行器绑的关节 id
qpos_idx = m.jnt_qposadr[act_jnt_ids]       # 14 个 qpos 地址
dof_idx = m.jnt_dofadr[act_jnt_ids]
```

这个坑在 `check_robust.py` 里已经修好，但 **`env.py` 里还是硬编码切片**——
意味着现在还无法用回差模型训练。

## 四、四类失败模式（可复用）

| 类型         | 症状                  | 根因                             | 定位手段              | 本轮实例                 |
| ---------- | ------------------- | ------------------------------ | ----------------- | -------------------- |
| **工程 bug** | 策略行为完全不对，但训练指标正常    | 导出/部署路径与训练不一致                  | 逐项对比训练与推理的输入构造    | exp1：归一化两边都少 → 假阳性   |
| **观测缺信息**  | 能力有上限，怎么调奖励都不行      | 策略看不见影响结果的那个量                  | 问"这个行为需要什么信息才能纠错" | exp3：没有 yaw，看不见自己朝哪  |
| **采样分布偏差** | 某个指令方向完全不响应或响应错     | 该组合的联合概率太低                     | 算联合概率，估样本数        | exp4：纯侧移只有 0.087%    |
| **奖励梯度消失** | 某项能力被"完全压死"，不是"学得差" | `exp(-e²/σ)` 在 σ 小时饱和成 0，梯度也 0 | 手算误差多大时得分塌到 0     | exp6：σ=0.1，偏 34° 就归零 |

**判断"是哪种"的三个问题**：

1. **训练时的 eval 指标和实测行为一致吗？** 不一致 → 大概率是工程 bug（导出/回放路径）
2. **这个行为需要的信息在观测里吗？** 不在 → 加观测，调奖励没用
3. **这个指令组合在训练里出现过多少次？** 少于几百次 → 是采样问题

## 五、方法论：五条纪律

### 1. 每轮只改 1~2 个变量

exp2 是唯一一次改了 4 个参数，因为那是"从不会走到会走"的质变，无法拆。之后全部单点改动。

exp5 的价值就在这里：它单独验证"调采样够不够"，答案是"不够"（只改善 15%），于是把这条路彻底排除，省下后续无谓尝试。

### 2. 训练指标不能判断行为

| 指标             | 看起来说明什么 | 实际不能说明什么                        |
| -------------- | ------- | ------------------------------- |
| `eval_reward`  | 策略在变好   | 走没走直、会不会转                       |
| `tracking_lin` | 速度跟得准   | 能不能走（exp6 是 479/2500，实测 12.3 m） |
| `heading`      | 航向对得准   | 直线性（exp7 是 39%，实测 21.6°）        |
| 回合长度           | 不摔      | 会不会走（站着也能跑满 1000）               |

**唯一可信的是逐指令实测**：`check_policy_mjx.py`（单指令 + 位移/偏航）、`check_all_dirs.py`（六方向）。

### 3. 5 秒测不出直线性，必须 30 秒

exp4 的 5 秒前进是 99.0%，看起来完美；30 秒偏了 −61.9°。

漂移是**累积误差**，短测试天然掩盖它。所有直线性结论必须来自 ≥ 30 秒的测试。

### 4. 门控比调权重更有效

exp6 尝试"用一个大权重项解决所有场景"，结果压死了另一项能力。  
exp7 改成"按指令分流"——同一个奖励项在不同指令下权重不同，两个能力就共存了。

**通用模式**：

```python
gate = exp(-(条件 / 尺度)²)                    # 光滑切换，不用 if
w_eff = w × (floor + (1 - floor) × gate)      # floor 保证不完全关闭
```

`floor` 不为 0 很重要：完全关闭会让另一个场景失去约束（exp7 若 floor=0，直线可能又漂）。

### 5. 数字对不上时先怀疑路径，不要怀疑算法

exp1 花了很久怀疑"PPO 学不会"，实际是导出少了归一化。  
判断顺序应该是：**导入/导出路径 → 观测拼装 → 奖励尺度 → 网络结构 → 算法超参**。

## 七、如果重来一次，顺序会是这样

1. **先建验收，再写代码**。`check_policy_mjx.py` 是第 6 轮才有的，前面几轮全靠猜。  
   正确的顺序应该是：写完 env 就先写"怎么判断它对不对"。
2. **观测一次给够**。yaw 那两维本该在第 3 步就想清楚——任何"需要保持某个量的积分"的任务，都要把那个量放进观测。
3. **奖励项先算梯度，再看权重**。给定 σ 就能算出"误差多大时得分塌到 0、梯度多大"，这一步手算五分钟，能省一轮训练。
4. **短测试只验方向，长测试才验精度**。5 秒测"能不能转"，30 秒测"走得直不直"，分工明确。
