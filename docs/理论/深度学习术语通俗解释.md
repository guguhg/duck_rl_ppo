# 深度学习术语通俗解释

> 配套《机器人深度学习.md》（分层结构表）与《深度学习笔记.md》（四维度表）。
> 目标：每个名词都能用一句人话讲清"它到底在干什么"，并说清它站在哪一层、为什么需要它。
> 全文不讲公式，只讲直觉；术语的严格定义仍以两份主文档为准。

---

## 第一部分　按层看：四层的典型技术在干什么

先记住一条：**层与层的区别是"多久做一次决定"，不是"谁更高级"**。感知 10~30 Hz、决策 0.2~2 Hz、技能控制 2~50 Hz、伺服 500 Hz~1 kHz。频率差一到两个数量级，所以不能拿上层的东西直接驱动下层。

### 1. 感知层（10~30 Hz）：把传感器数据变成"能用几何量"

| 技术 | 人话解释 | 生活类比 | 输出什么 |
|---|---|---|---|
| **CNN 检测分割** | 用卷积网络扫图像，找出"有没有、在哪、是什么、每个像素归谁" | 一眼扫过桌面，凭形状认出杯子并指出位置 | 包围盒 + 类别 + 掩码 |
| **点云网络** | 直接吃一堆三维点（激光雷达/深度相机），不转成图片 | 闭眼摸物体，靠轮廓和距离认形状 | 3D 框、逐点标签、6D 位姿 |
| **VLM 编码器** | 把图像和文字编进同一套向量空间，让"图"和"话"能互相对上 | 给图和词贴同一套标签，说"红色杯子"就能找到对应那块 | 图/文的联合特征向量 |

**最容易搞错的一点**：感知层的活不是"输出特征图"，而是**输出下游能直接用的几何量**（位姿、框、掩码）。特征图只是中间产物，交不出几何量等于没干完。

**为什么必须快**：感知在闭环里，慢一拍就意味着决策拿到的是过时世界。

### 2. 决策层（0.2~2 Hz）：决定"做什么、先做什么"

| 技术 | 人话解释 | 生活类比 | 局限 |
|---|---|---|---|
| **LLM 任务分解** | 把一句人话拆成一串可执行的子任务/技能调用 | 包工头看图纸，分派给不同工种 | 会瞎编，不懂物理可行不可行 |
| **深度 RL** | 用奖励试错，学"这个局面该往哪走、先干哪件事" | 训练狗：做对了给零食，做错了没得吃 | 奖励设计难，样本需求巨大 |
| **状态机** | 手写"当前处于哪个状态、满足什么条件跳到哪个状态" | 红绿灯、自动售货机 | 状态一多就爆炸，写不出"灵活应变" |

**状态机为什么在决策层还活着**：它不是学习，但它**确定性、可审计、可测试**。凡是涉及安全的分支（急停、超限、异常回退），宁可手写状态机也不用神经网络——学习模块不进安全链。

**LLM 的边界**：它输出的是"动作原语序列"，后面必须接一道可执行性检查（这个技能存在吗？参数越界吗？目标可达吗？）。没有这道闸，LLM 就是一个会说漂亮话的幻觉源。

### 3. 技能控制层（2~50 Hz）：把"决定"变成"动作序列"

| 技术 | 人话解释 | 生活类比 | 数据需求 |
|---|---|---|---|
| **RL 运动策略** | 一个神经网络，看状态直接吐关节目标，50 Hz | 小脑：摔了上万次练出来的肌肉记忆 | 仿真里千万~亿级交互步 |
| **模仿学习** | 人遥操作示范，网络学"看到这样就该这样动" | 学徒照抄师傅的手法 | 几十~几百条示教 |
| **扩散策略** | 从一团噪声开始，一步步去噪，生成一整段动作 | 先糊一团墨，再慢慢描成一幅画；同一句话能画出不同但都对 | 与模仿学习同量级 |
| **VLA** | 图 + 语言指令 → 动作 | 听得懂人话的操作工 | 大规模多任务数据或本机微调 |

**为什么行走/平衡必须用 RL**：这类技能**没法示范**。人没法"演示"怎么在一只脚打滑时保持平衡——那种反应是毫秒级的、说不出来的。示范不出来，模仿学习就断了，只剩奖励试错这条路。

**为什么抓取/装配偏爱模仿学习**：人手怎么做是看得见、录得下来的。设计一个"抓得稳"的奖励函数反而比录几条示范难得多。

**扩散策略的代价在哪**：多步去噪换来了多峰、平滑的动作，但推理慢。所以它适合 2~10 Hz 的技能层，不能塞进 1 kHz 的伺服环。

### 4. 伺服层（500 Hz~1 kHz）：经典控制的四件套

这一层**几乎全是经典控制**，也是"用深度学习"不等于"全用神经网络"的最直接证据。越是底层，越依赖确定性。

| 技术 | 人话解释 | 生活类比 |
|---|---|---|
| **PID** | 按误差算输出：P 看现在差多少，I 补长期累积的偏差，D 抑制冲过头 | 开车握方向盘微调：偏了就回一点，一直偏就一直加力，快回正了提前收手 |
| **MPC** | 每周期往前预测一小段，解一个最优化，只执行第一步，下一步重算 | 下棋看三步，走一步，再看三步 |
| **WBC** | 多个任务同时要，按优先级分配：先保平衡，再走，最后才管摆手 | 端着一杯满水走路：水不能洒是最高优先级，走姿好看排最后 |
| **轨迹插补** | 把 50 Hz 的目标点之间补成 1 kHz 的连续指令 | 动画的中间帧；不补就会出现台阶，一台阶就是一次抖动或异响 |

**这四件套的分工**：插补解决"频率落差"，PID 解决"跟踪"，MPC 解决"带约束的预测"，WBC 解决"多任务冲突"。缺哪个都会在某个场景露馅。

**为什么鸭子是"策略 50 Hz + PD 1 kHz"**：上层神经网络想不快也没必要快（推理只占预算 0.09%），下层必须快才能压住摩擦、间隙和负载变化。中间靠插值衔接——这就是"10 Hz 推理直接接 1 kHz 伺服会抖"这条误区的由来。

## 第二部分　按维度看：四个坐标的 16 个取值

第二张图的关键认知：**这不是"选一个"，而是四个坐标定一个组合**。

> 类比：说"红色是汽车的一种"是错的，因为红色属于"颜色"这个维度。同理，"监督学习是深度学习的一种"也是错的——它属于"训练范式"这个维度。

### 维度一　网络结构（用什么工具算）

| 取值 | 人话解释 | 生活类比 | 什么时候用 |
|---|---|---|---|
| **MLP 全连接** | 每个神经元和上一层所有神经元相连，本质是一堆矩阵乘法 | 全体开会，人人对每个议题都发言 | 低维、人工拼好的向量（鸭子的 101 维） |
| **CNN 卷积** | 用同一组小卷积核滑过整张图，只看局部花纹，权重共享 | 拿同一把小放大镜扫遍全图 | 图像、有空间邻接关系的数据 |
| **RNN / LSTM** | 按时间一步步读，带"记忆"把前文带到后文 | 边听边记笔记，记住前面说了什么 | IMU/力/关节的时序信号 |
| **Transformer** | 注意力机制：任意两个位置可以直接互看，不受距离限制 | 开会时谁相关就点谁发言，不看座位顺序 | 长程依赖、多模态融合 |

**为什么鸭子用 MLP 就够**：输入是人工拼好的 101 维向量，没有图像的空间邻接可挖；时序信息已经用 `last_action×3` 手工塞进去了。用 CNN 是拿错归纳偏置，用 Transformer 是杀鸡用牛刀——**结构要匹配数据的形状，不是越新越好**。

### 维度二　训练范式（怎么学出来）

| 取值 | 人话解释 | 生活类比 | 机器人里干嘛 |
|---|---|---|---|
| **监督学习** | 每步都有标准答案，学的是"复制" | 有答案的练习册 | 检测、6D 位姿估计 |
| **无监督学习** | 没有答案，自己从数据里找结构 | 把一箱零件按相似度分堆 | 异常检测、聚类 |
| **自监督学习** | 自己给自己造答案（遮住一部分让它猜） | 做完形填空，答案本来就在句子里 | 大模型预训练 |
| **强化学习** | 没有正确答案，只有分数，而且常常延迟几十步 | 训狗、打游戏刷分 | 走路、平衡、灵巧操作 |
| **模仿学习** | 有人做给你看，学的是"照抄" | 学徒看师傅做一遍 | 抓取、装配 |
| **离线 RL** | 只用一堆积压数据学，不许再下场试 | 只看比赛录像学，不许上场练 | 不敢在线试错的场景 |

**三种范式的本质差异**（这句能背下来就够用）：

- 监督 → 学**复制**
- 强化 → 学**试错**
- 模仿 → 学**照抄**（快，但天花板由示范质量决定）

**为什么机器人行走几乎只能是 RL**：平衡是靠"摔倒"学出来的，而人没法示范"打滑瞬间怎么救"。示范不出来的技能，模仿学习无从下手。

### 维度三　任务类型（干什么）

| 取值 | 人话解释 | 生活类比 |
|---|---|---|
| **分类** | 从固定几类里选一个 | 邮件分垃圾/正常 |
| **检测** | 找出"在哪"和"是什么" | 合影里圈出每个人并标名字 |
| **分割** | 给每个像素贴标签 | 给照片逐像素上色分类 |
| **回归** | 输出连续数值 | 报一个温度读数 |
| **位姿** | 回归的特例：3 平移 + 3 旋转 | 不光认出手，还要说出它的朝向 |
| **生成** | 造出新的样本（图、动作序列） | 不是判断，是创作 |

**鸭子在哪个格子**：**回归**。输出 14 个连续的关节角度（弧度），不是"猫/狗"这种离散类别。判断标准很简单——**输出是连续量就是回归，是离散类别就是分类**。

### 维度四　模型形态（输入输出长啥样）

| 取值 | 人话解释 | 生活类比 |
|---|---|---|
| **策略网络** | 状态 → 动作，一对一 | 条件反射：看到这样就这样动 |
| **VLA** | 图像 + 语言 → 动作 | 听得懂指令的操作工 |
| **扩散策略** | 状态(+图) → 一整段动作，靠去噪生成 | 先糊墨再描画，一次画一小段 |
| **动作分块 ACT** | 一次预测一串动作，而不是一次一个 | 一次排好接下来几个拍子的舞步，不是一步步挪 |

**ACT 解决的真问题**：一次只输出一个动作，误差会一步步累积，而且推理频率被死死绑在上层。改成一次输出一段（chunk），既降低累积误差，也允许"慢慢算、快点执行"。

## 第三部分　最容易混的四个边界

| 混淆点 | 正确认知 |
|---|---|
| **把 VLA 当成 RL 的一类** | VLA 是**模型形态**（图+文→动作长什么样），RL 是**训练范式**（怎么学）。VLA 可以用模仿学习训，也可以再用 RL 微调 |
| **把扩散策略当成训练范式** | 扩散是**动作生成器**（去噪过程），通常用模仿学习来训练它 |
| **把监督学习当成"深度学习的一种"** | 它是"训练范式"这一维的取值，与强化学习**并列**，不是包含关系 |
| **以为"用了深度学习就不需要 PID/MPC"** | 伺服层几乎全是经典控制。学习模块负责"该做什么"，经典控制负责"稳稳做到" |

## 第四部分　一句话把两层接口说清

整条链路上最容易出事的地方不是任何单个算法，而是**层与层的接口**：

| 接口 | 上游给什么 | 下游要什么 | 出事的典型症状 |
|---|---|---|---|
| 决策 → 技能 | 动作原语序列 | 该技能存在、参数在范围内 | 调用一个不存在的技能，或给个越界参数 |
| 技能 → 伺服 | 50 Hz 关节目标 | 1 kHz 连续指令 | 不插补 → 台阶、抖动、异响 |
| 感知 → 决策 | 位姿/框/掩码 | 时间戳对齐、坐标系一致 | 拿到过时或错坐标的世界 |

**记住这条**：分层架构的第一原则不是"用什么算法"，而是"**频率差一到两个数量级，接口必须有缓冲、插补和对齐**"。
